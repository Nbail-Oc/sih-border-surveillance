# IBVAP Feature Mapping — What Frigate Already Solves

Source reviewed: [github.com/blakeblackshear/frigate](https://github.com/blakeblackshear/frigate) README + [docs.frigate.video](https://docs.frigate.video) (Semantic Search, Face Recognition, LPR, Zones/Masks pages).

Legend: ✅ Fully reusable · 🟡 Partially reusable (needs tweaks/extension) · ❌ Not covered, build from scratch

---

| Feature Needed in Final Product | What Can Be Reused |
|---|---|
| **Live multi-camera dashboard** | ✅ **Frigate** — Built-in live dashboard with per-camera tiles + a dynamic combined "Birdseye" view of all cameras. Works out of the box via RTSP/IP camera ingestion. |
| **24/7 recording with smart retention** | ✅ **Frigate** — Native 24/7 recording feature, with retention rules based on whether an object was detected (saves storage vs. recording everything at full retention). |
| **Human / person detection** | ✅ **Frigate** — Built-in `person` object detection via TensorFlow/COCO model (or Frigate+ custom models), runs locally in real time. |
| **Vehicle detection & basic classification** (car, motorcycle, etc.) | ✅ **Frigate** — Built-in `car`, `motorcycle`, `bus` etc. object classes from the default model. *Tweak needed:* our PS wants finer classes (truck, tractor, military vehicle) — would need a **Frigate+ custom-trained model** or a separate classifier stage. |
| **Automatic Number Plate Recognition (ANPR)** | ✅ **Frigate — License Plate Recognition (LPR) module.** Detects `car`/`motorcycle`, runs YOLOv9 plate detector + PaddleOCR to read plate text, supports "known plates" matching (regex + fuzzy `match_distance`), stores `recognized_license_plate` per tracked object. *Tweak:* Indian plate format regex, and possibly a higher-zoom "dedicated LPR camera" config for border-road cams. |
| **Face detection** | ✅ **Frigate — Face Recognition module.** Detects faces once a `person` is found (CV2 lightweight DNN, or native if using a face-detecting model). |
| **Face recognition / identity tagging** (name a face, recognize again) | ✅ **Frigate — Face Recognition module.** FaceNet (small/CPU) or ArcFace (large/GPU) embeddings; unknown faces logged in a "Train" tab, can be assigned a name via the **Face Library** UI, future matches auto-tagged as `sub_label`. This is effectively idea #3 and #11 (name a face → recognized everywhere after). |
| **Multi-angle face capture / "Google Photos"-style face gallery** | 🟡 **Frigate — Face Library "Recent Recognitions" tab.** Groups captured face crops per person and lets you pick good ones for training. *Tweak needed:* it's built for *training the model*, not as a polished user-facing gallery UI (idea #11's "zoomed face + collage" sidebar) — we'd build a nicer front-end on top of Frigate's face data/API. |
| **Natural language search** ("a person in a red shirt") | 🟡 **Frigate — Semantic Search ("Explore" page).** Uses Jina CLIP embeddings for `text → image` and `image → image` similarity search over tracked-object thumbnails, runs fully locally. *Tweak:* works best as an "image caption"-style query on a single object's thumbnail, not a full sentence-level search that highlights a multi-camera timeline exactly as idea #4 describes — timeline highlighting UI would need custom building on top of Frigate's search API results. |
| **Reverse image search** (upload photo → find matches) | ✅ **Frigate — Semantic Search `image → image`.** Click "Find Similar" on any tracked object thumbnail to retrieve visually similar past detections. *Tweak:* needs a simple "upload your own image" entry point wired to the same embedding search (Frigate's default flow starts from an existing detection, not an external upload). |
| **Person re-identification / cross-camera tracking history** (idea #5, #8 — same person, same ID, "seen here before", frame-out timer) | ❌ **Gap.** Frigate tracks an object *within* a camera session and can recognize a *known face* across cameras via Face Recognition, but it does not do full body re-identification (linking an *unrecognized* person's movement across multiple cameras into one persistent trail with a running "time in frame" counter). This needs a custom Re-ID module (e.g., a person Re-ID embedding model like OSNet/FastReID) layered on top of Frigate's tracked-object events. |
| **Skeleton / pose / hand / gaze tracking for suspicious-behavior analysis** (idea #7) | ❌ **Gap.** Not part of Frigate at all. Would need a separate pose-estimation model (e.g., MediaPipe Pose, YOLO-Pose, OpenPose) running as an additional enrichment stage, feeding a custom rule engine for behaviors like "crouching," "hands near fence," etc. |
| **Region of Interest (ROI) / polygon zones** | ✅ **Frigate — Zones.** Draw polygon zones per camera in the UI; supports restricting alerts/detections to a zone, per-object-type zone rules, **loitering time**, zone "inertia" (anti-jitter), and even **speed estimation** through a zone using real-world distance calibration. |
| **Virtual fence line-crossing detection** | 🟡 **Frigate — Zones (partial fit).** Frigate's zones are presence-based polygons (object's bottom-center point inside/outside a shape), not a literal directional "line-crossing" trigger like UniFi's. You can approximate a line by using a thin zone + checking which zone an object came from/went to, but a true "crossed inbound vs outbound" event needs custom logic on top of Frigate's zone-enter/zone-exit events. |
| **Suspicious activity detection** (loitering, unattended object, fighting, lying down) | 🟡 **Partial.** Frigate's **Zone Loitering** covers "person lingering too long" directly. Fighting, lying-down posture, and object-in-hand detection are **not** built in — these need the custom pose/behavior module mentioned above, or Frigate's **Generative AI object description** feature (asks a vision-LLM to describe what's happening) as a lighter-weight stand-in. |
| **Night-time movement detection** | 🟡 **Partial.** Frigate performs detection on whatever video stream it's given — it works fine on IR/night-vision footage from the camera itself, but Frigate doesn't add its own low-light enhancement or a distinct "night mode" trigger. If existing BOP cameras have decent IR, this mostly "just works"; if not, a low-light enhancement pre-processing step would need to be added. |
| **Real-time alert generation** | ✅ **Frigate — Notifications + Review system.** Native push notifications (Web Push/VAPID), a Review page that classifies events into Alerts vs Detections, and **Triggers** that fire custom actions (notification, label, attribute) when a thumbnail/description match occurs above a similarity threshold — usable as a lightweight "custom alarm" builder (idea #9). |
| **Event logging / historical searchable table** | ✅ **Frigate — Review page + Explore page.** Filterable by camera, object label, zone, time range, and (with LPR/Face enabled) by recognized plate or person. Matches idea #9 closely. |
| **Custom alarms on specific event types** | 🟡 **Frigate — Triggers (partial fit).** Triggers automate a notification/label when a *visual or description match* occurs, which covers some custom-alarm use cases (e.g. "alert me if this specific vehicle/person reappears"). It doesn't yet give a generic rule-builder UI for arbitrary event types like "tampering + fighting + object-in-hand" in one profile the way idea #9 envisions — would need a rules layer on top. |
| **Camera tampering detection** | ❌ **Gap.** Not present in Frigate's documented feature set. Would need a dedicated tamper-detection check (e.g., detect sudden full-frame change, lens covering, defocus) built separately. |
| **Integration with existing command & control systems** | ✅ **Frigate — MQTT + HTTP API.** Publishes all events/detections over MQTT and exposes a full HTTP API (events, review, exports, media, auth) — straightforward to bridge into an existing C2 system. |
| **Customizable dashboard layout** (drag-and-drop widgets, resize, add map/stat widgets) | ❌ **Gap.** Frigate's dashboard is a fixed camera-grid + Birdseye view, not a drag-and-drop widget builder with map/stat/alert widgets like idea #1/#14. This front-end would need to be custom-built (Frigate's API can feed the data; the layout UI itself is new work). |
| **Geographic map of camera/BOP locations with live pins** | ❌ **Gap.** Not part of Frigate. Would be a custom map widget (e.g., Leaflet/Mapbox) built on top of camera metadata you define yourself. |
| **Vehicle "watchlist" flagging** (known plate = alert) | ✅ **Frigate — LPR `known_plates` + Triggers.** Define known/flagged plates with fuzzy matching (`match_distance`), auto-tag as `sub_label`, and combine with Triggers/Notifications for an instant alert — matches idea #13's "flagged vehicle" concept well. |

## Summary — Where to Focus New Engineering Effort

Frigate genuinely covers a **large chunk** of the problem statement (probably 55–60% of it) — especially the "boring but essential" plumbing: ingesting IP camera streams, real-time object detection, recording/retention, face recognition, LPR, zone-based intrusion detection, semantic search, alerting, and system integration (MQTT/API). That's a huge head start.

What's genuinely **new work** for IBVAP, layered on top of Frigate:

1. **Cross-camera person re-identification** with a persistent ID + "time in frame" timeline (idea #5, #8) — the single biggest gap.
2. **Pose/skeleton-based behavior analysis** (idea #7) for real suspicious-activity detection beyond loitering.
3. **True directional line-crossing** (vs. Frigate's presence-based zones).
4. **Camera tampering detection.**
5. **The custom dashboard UI** — drag-and-drop widgets, border map with live pins, polished face-gallery/person-profile sidebar, NLP search with cross-camera timeline highlighting. Frigate's API/data can power all of this, but the front-end experience you sketched (ideas #1, #2, #5, #9, #14) is a fresh build.

A sensible architecture: **run Frigate as the core NVR + detection/enrichment engine**, and build IBVAP's own web front-end + a "behavior/Re-ID microservice" that consumes Frigate's MQTT events and HTTP API, adding the missing intelligence layers on top.
